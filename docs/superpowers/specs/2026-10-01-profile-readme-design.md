# GitHub profile README — design

- **Date:** 2026-10-01
- **Status:** Approved by owner in chat
- **Repo:** `nayots/nayots` (GitHub profile repository)

## Goal

Replace the 2021 portfolio repo with a profile README that is a visual
masterpiece in the nayots identity — *a name rendered as luminous stardust* —
then make the repository public so GitHub shows it on <https://github.com/nayots>.

## Decisions

| Topic | Decision |
|---|---|
| Old `portfolio/` app + Cloud Run workflow | Removed from master (kept in history). nayots.com now ships from `nayots_homepage` on Vercel. |
| Visual approach | Custom, self-contained, animated SVGs in the brand palette. No third-party stats cards. Official marks copied from `nayots_branding`. |
| Headline | "Software engineer" — breadth (.NET, AWS, frontend, infrastructure, AI), not a stack inventory. |
| Projects shown | Public only: `ai-agent-usage-monitor`, nayots.com. |
| Fonts | Space Grotesk (OFL), subset and embedded as base64 in each SVG. |
| Raster images | Only if a design step needs one; generated by Codex. Marks are never generated. |
| Go-public timing | Last, after the finished README is on master. |

## Page composition (top to bottom)

1. **Hero** — `assets/hero.svg`, navy scene plate (~1200×380). Official particle
   wordmark embedded verbatim, slow starfield twinkle, one line:
   *Stoyan Grigorov · software engineer · Sofia*. Theme-neutral plate.
2. **Intro** — two or three sentences of Markdown, ending on *ad astra per aspera*.
3. **Constellations** — `assets/constellations.svg`: five constellations
   (.NET, AWS, Frontend, Infrastructure, AI), a few named stars each, lines draw in.
4. **Featured work** — two linked SVG cards, `assets/card-usage-monitor.svg` →
   repo, `assets/card-nayots.svg` → nayots.com. Plain `<img>` inside `<a>`.
5. **Your year as a sky** — `assets/sky.svg`, generated daily by
   `.github/workflows/sky.yml` running `scripts/render-sky.mjs`: contribution
   calendar → star map (one star per day, brightness = activity, gold flares on
   peak days), plus totals.
6. **Footer** — flat monogram, nayots.com and LinkedIn as text links.

## Constraints

See `AGENTS.md` → "How GitHub renders this README". Key ones: no scripts or
external resources inside SVGs; no `<picture>` inside `<a>`; legible at 360px;
reduced-motion honoured; each asset under ~500 KB; palette locked.

## Generator (`scripts/render-sky.mjs`)

- Node ≥ 20, zero dependencies (`fetch` built in).
- Input: GraphQL `user(login:"nayots").contributionsCollection.contributionCalendar`
  using `GITHUB_TOKEN`; or `--fixture <file>` for offline rendering.
- Output: `assets/sky.svg`, deterministic for a given calendar (seeded jitter),
  so the workflow only commits when the data actually changed.
- Failure: non-zero exit and no file write on API error — the last good SVG stays.

## Workflow (`.github/workflows/sky.yml`)

- Triggers: daily cron, `workflow_dispatch`.
- `permissions: contents: write`; commits only if `assets/sky.svg` changed.

## Verification

GitHub `/markdown` API render check; browser screenshots of every SVG at 360px
and 830px, light and dark grounds, reduced motion; asset sizes; one
`workflow_dispatch` run after push.
