# nayots — GitHub profile repository

This is the special **`nayots/nayots`** repository: GitHub renders its `README.md`
on the profile page at <https://github.com/nayots>. It contains nothing else of
substance — the README, the images it shows, and the small generator that keeps
one of those images live.

**Agents: read this file fully before touching anything.** The design spec is
`docs/superpowers/specs/2026-10-01-profile-readme-design.md`.

---

## Goal

A visual masterpiece of a profile page, in the nayots identity: *a name rendered
as luminous stardust.* Restraint over volume — no badge walls, no third-party
stats cards, no emoji bullet lists.

## Repo layout

```
README.md                    ← the profile page itself
PRODUCT.md                   ← product truth (Impeccable)
assets/
  brand/                     ← verbatim copies from nayots_branding (never edit) + NOTICE.md
  hero.svg, constellations.svg, work-*.svg
                             ← GENERATED by scripts/build-plates.mjs — edit the script, not the SVG
  sky.svg                    ← GENERATED daily by scripts/render-sky.mjs — do not hand-edit
scripts/
  lib/sky.mjs                ← shared sky vocabulary: palette, plate frame, starfield, glints, fonts
  lib/calendar.mjs           ← pure contribution-calendar maths (tested)
  build-plates.mjs           ← hero, constellations, work plates
  render-sky.mjs             ← contribution calendar → star map (zero dependencies)
  fonts/                     ← Space Grotesk 500/700 WOFF2 subsets, advance widths, OFL
  source/                    ← sourced rasters with provenance sidecars
.github/workflows/sky.yml    ← daily cron + workflow_dispatch, commits assets/sky.svg if changed
.impeccable/surfaces/        ← direction contract for the README surface
docs/superpowers/specs/      ← design spec
```

All plates share one 840-unit-wide viewBox, a 20-unit corner radius and the
three star classes (dust, star, gold four-point glint with the keystone's own
0.306 curve ratio). Entrance animations start from a visible state — text and
stars must never depend on an animation running to be seen.

## How GitHub renders this README (hard constraints)

- Every image is shown through `<img>`, proxied by camo. Inside an SVG that means:
  **CSS and SMIL animation work; scripts, external fonts, external images and
  `<foreignObject>` do not.** Embed fonts and rasters as `data:` URIs.
- The HTML sanitizer keeps `<picture>`, `<source>`, `<img>`, `<a>`, `<p align>`,
  `<br>`, `<sub>`, `<sup>`, `<details>`. It strips `style`, `class`, `<script>`, `<svg>`
  inline, and `<iframe>`.
- **Never put `<picture>` inside `<a>`.** The sanitizer lifts the `<img>` out of the
  `<picture>` and re-links it to the image file, killing the theme swap. A plain
  `<img>` inside `<a>` is fine.
- Images are scaled to the column width (~830px on desktop, ~100% on mobile).
  Design every SVG to stay legible at 360px wide.
- Honour `@media (prefers-reduced-motion: reduce)` inside every animated SVG.
- Keep each asset under ~500 KB; camo is slow with large SVGs.

## Brand lock

Source of truth: the sibling repo `nayots_branding` (`BRAND.md`,
`brand/tokens/tokens.json`). Use the `nayots-branding` skill when choosing assets.

- **Copy marks, never recreate them.** Keep original file names. No recolour,
  glow, outline, container, badge or tagline on a mark.
- Particle (stardust) marks only on deep navy and at ≥64px; flat marks elsewhere.
- **No colours outside the palette:** `#04060D` `#F1F5FF` `#99D1FF` `#FFBD57`
  `#AAD7FF` `#FFCD78` `#141C3A` `#0A0F21` `#05070F` `#030509` (+ `#17517F` on light
  grounds only). Opacity variations of these are fine.
- Type: Space Grotesk. Brand display text is 700, lowercase, tracking −0.035em.
- Brand assets are proprietary (all rights reserved) even though the repo's
  `LICENSE` is GPL-3.0 — see `assets/brand/NOTICE.md`.

## Commands

```bash
node scripts/build-plates.mjs                    # rebuild hero, constellations, work plates
node scripts/render-sky.mjs                      # regenerate assets/sky.svg (needs GITHUB_TOKEN)
node scripts/render-sky.mjs --fixture <json>     # render from a saved calendar, offline
node --test "scripts/**/*.test.mjs"              # unit tests (quote the glob; a bare directory fails on Node 26)
```

Font subsets are rebuilt only when new characters are needed: instance Space
Grotesk (OFL, google/fonts) at 500 and 700 with fontTools, subset to printable
ASCII plus `· — – ’ … → nbsp`, write WOFF2 and the advance-width table to
`scripts/fonts/metrics.json`.

## Verification (after any change)

1. Render the README through GitHub's markdown API and confirm nothing was stripped:
   `gh api -X POST /markdown -f mode=gfm -f context=nayots/nayots -f text="$(cat README.md)"`.
2. Open every SVG in a browser at 360px and 830px wide, light and dark page
   backgrounds, with and without reduced motion. Headless screenshots do not
   advance CSS animations inside `<img>` SVGs — capture with
   `--force-prefers-reduced-motion` or the shot shows start states.
3. `ls -la assets` — every file under ~500 KB.
4. After pushing, trigger `sky.yml` with `workflow_dispatch` and check the commit it makes.
